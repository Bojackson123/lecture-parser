# P5-02 — Chunk pass: `merge_chunks`, chunk prompt, `generate_topic()`, recorded-response fixture
Phase 5 · Depends on: P5-01 · Size: L

## Goal

The per-chunk half of plan §4.2 ("asked about one slide and its two minutes of
explanation, it produces notes with real detail"): a pure density merge settling plan
§9.1, a chunk prompt that protects the two disproportionate-value schema fields —
`Callout(EXAM)` ("this will be on the exam" is cue 14, and the fixtures README row
promises "Phase 5 must emit `Callout(kind=EXAM)` anchored here") and
`Callout(UNCERTAIN)` (the escape hatch that prevents hallucinated smoothing, "this
pipeline's main failure mode") — and `generate_topic()`, which turns one `Chunk` into
one `Topic` with its §7.2 stable id and its anchor taken verbatim from the chunk span.
The hand-written recorded-response fixture closes the loop the fixtures were designed
for: `ingest → align → generate(fake)` reproduces the `week01` lec01 topics that
Phase 3 already renders.

## Decisions & notes

- **The density floor is 100 words, not §9.1's suggested ~120.** The committed
  chunks weigh 81/120/103/103 words: at 120, slides 2 and 3 would merge into one
  topic and sever the chunk↔`week01`-topic correspondence the P4 fixtures were built
  around. §9.1 offered 120 as a starting point to tune; 100 keeps the canonical
  fixture intact while still merging genuinely tiny chunks, and P5-04's
  `--min-words` is the tuning knob for real lectures (where 120+ may well be right).
- **Gap chunks fence merging.** Board work merged into a slide chunk would cite
  slides the lecturer wasn't on — the anchor-honesty rule — and a slide chunk merged
  into a gap would erase the §4.1 gap signal Phase 9 triggers on. A fenced
  under-floor chunk (the fixture's 81-word chunk 1) stays: a thin topic is honest,
  a mis-cited one is not.
- **Merge before spend.** Merging after generation would pay tokens for topics that
  are then thrown away and would orphan their §7.2 ids; `merge_chunks` is pure and
  runs before any request, so `--dry-run` (P5-04) shows exactly what will be
  prompted.
- **Request keys are `chunk:` + `topic_id(...)`.** One id scheme end to end: the
  fake's fixture keys, the topic ids, and log lines all name the same coordinates,
  and the recorded fixture survives prompt tuning because keys don't hash content
  (P5-01 decision).
- **The recorded fixture is PPTX-bound.** Its `s3-3` response embeds the PPTX image
  id; the PDF deck's differs (`img-9ccb398ff27a71d1` — pypdf re-encodes, P2-03
  invariant "never join decks on image id across formats"), so the fake pipeline
  runs on PPTX+VTT. Cross-format behaviour is pinned where it actually lives — in
  `chunk_prompt` (PDF: no notes, PDF ids) — not by running the whole fake pipeline
  twice. Cross-format *alignment* parity was already proven in P4-03.
- **The prompt embeds the pydantic schema.** `ChunkNotes.model_json_schema()` is the
  single source of truth; a schema edit changes the prompt automatically and the
  pinned fragment test fails if the embedding is dropped, so prompt and validator
  cannot drift apart.
- **`ChunkNotes` reuses the IR's `Node`/`CardSeed` types wholesale.** The model
  writes IR, not a parallel dialect — plan §2.1's whole argument. If Phase 6 forces
  an IR change, mypy finds this seam like every other (plan §10).
